# openthai-systemone-server

One-command self-hosting for [iapp/OpenThai-SystemOne](https://huggingface.co/iapp/OpenThai-SystemOne) — a 0.8B Thai + English decision model.

`main.sh` sets up everything: system deps, Python venv, the model package, a systemd service, and model preloading.

## Quick start

```bash
chmod +x main.sh
./main.sh install
```

When it finishes you have a warm endpoint:

```bash
curl -s localhost:8000/v1/systemone \
  -H 'content-type: application/json' \
  -d '{"state":"โดนหักเงินซ้ำสองครั้ง ขอเงินคืนด่วน",
       "questions":{"refund":{"type":"noul","instructions":"ลูกค้าขอเงินคืนอย่างชัดเจนหรือไม่"}}}'
```

## Commands

| Command | What it does |
|---|---|
| `install` | full setup — idempotent, safe to re-run |
| `status` | service state + health check |
| `bench [n]` | latency percentiles |
| `logs [n] [f]` | journal (`f` to follow) |
| `warm` | wait for readiness, then one request |
| `start` `stop` `restart` | service control |
| `doctor` | diagnose venv, gcc, Python.h, CUDA, unit, port |
| `uninstall` | stop, disable, remove the unit |
| `run` | foreground, for debugging |

## Requirements

- Linux with systemd
- NVIDIA GPU (falls back to CPU — much slower)
- `uv` and `git`
- sudo, unless you use `MODE=user`

## Configuration

```bash
PORT=9000 ./main.sh install      # bind elsewhere
MODE=user ./main.sh install      # no sudo, systemd --user
WORKERS=4 ./main.sh install      # parallel, but 4 model copies on the GPU
```

Variables: `HOST` `PORT` `MODEL` `HF_HOME` `SERVICE` `WORKERS` `MODE`

## Why the first request isn't slow

Upstream loads the model lazily on the first POST — a ~60s stall plus a Triton kernel compile. `serve.py` (generated by `main.sh`) preloads the weights and runs one dummy decision **before** opening the socket, so the first real request is already warm.

## Notes

- The endpoint has **no authentication**. Keep it on a trusted network, or put a proxy in front.
- `WORKERS=1` (default) serializes requests. Each extra worker loads its own ~2GB copy of the model.
- Run `doctor` first when something breaks.
